# Suite 2 — Duration Selection Redesign

> **Story:** Replace separate seconds/minutes/hours tabs with a single unified wheel picker under one "Time" tab, preserving all existing duration rules per trade type and market.
> **Owner:** @farabi-deriv
> **Result of manual execution (2026-08-03): strong pass.** Every case executed matched the expected result and the Figma spec exactly, including validation copy, range helper text, and gated Save behavior. This is the most solidly-implemented suite so far.

## Confirmed Behavior (exploration + Figma + manual execution)

- **Mobile** (500×850): Duration opens a bottom sheet with 3 top tabs — `Ticks` / `Time` / `End time`. `Ticks` is a single-column wheel. `Time` is a **unified 3-column wheel** (hr / min / sec) — matches the issue's ask. Selecting a value auto-applies immediately; no Save button; sheet closes on backdrop tap.
- **Desktop** (≥1280): Duration opens a popover with a **left nav of 5 separate tabs** — `Ticks` / `Seconds` / `Minutes` / `Hours` / `End time` (or 4 tabs, no `Seconds`, for markets like Forex that don't support second-level durations — see DUR-11). Each tab has `Quick picks` (preset chips, apply instantly, no Save) / `Custom` (numeric input + range helper + gated Save) sub-tabs. **This is the intended design**, confirmed both by Figma and consistent behavior across markets.
- The Custom sub-tab shows a labeled input, a range helper (e.g. "Range: 15 - 60 seconds"), and a **Save** button disabled until a valid value is entered — confirmed pixel-for-pixel matching Figma.

## Preconditions (all cases)

- Trade type = Rise/Fall unless noted (duration UI is shared across trade types that support duration)
- Both viewports unless a case is platform-specific
- Executed on Demo account (10,004.79 USD) on `redesign-trade-selection.derivatives-trader.pages.dev`

## Notes

1. All Figma-predicted details were confirmed exactly as documented: Custom tab range helper text, disabled/enabled Save gating, and per-market/per-type validation messaging.
2. DUR-13 as originally written doesn't map cleanly onto this build's architecture — "trade type" isn't switched in-place on an existing duration picker; each trade type/market combination is its own tab with independently-initialized duration state. Recommend removing/rewriting DUR-13 to test "does a newly-opened tab correctly initialize duration limits for its own trade type" instead, which is really a Suite 6 concern (see TABS-04).
