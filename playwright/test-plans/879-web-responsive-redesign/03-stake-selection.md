# Suite 3 — Stake Selection Redesign

> **Story:** Simplify stake input with optimized presets, fewer steps, and removal of the unnecessary "Save" button while maintaining production-accurate validation.
> **Owner:** @farabi-deriv

## Confirmed Behavior (exploration + Figma)

- **Mobile** (500×850, staging preview): Stake opens a bottom sheet with a numeric input, 6 preset chips (1/5/10/20/50/100 USD), a `Max payout` / `Payout (Rise)` summary, and a visible **"Save"** button at the bottom, all on one screen (no tab split between chips and manual entry).
- **Desktop** (≥1280, staging preview + confirmed in Figma "Quick picks and custom UI update" section): Stake opens a popover split into two sub-tabs: **`Quick picks`** (preset chips only — 1/5/10/20/50/75 USD in the Figma sample — applies instantly, **no Save button**) and **`Custom`** (numeric input + `Max payout`/`Payout` rows + a **Save** button).
- **Figma resolves the "Save button removal" ask**: the issue's call to remove the "unnecessary Save button" refers to removing it from the preset-chip path, not from manual/custom entry — Save is retained specifically for Custom, by design. What's still unconfirmed is whether mobile's single combined sheet requires Save even when the user only taps a chip (no custom entry involved) — if so, mobile does not match the desktop pattern and story #3's intent (see STAKE-04/STAKE-16).

## Preconditions (all cases)

- Trade type = Rise/Fall unless noted
- Both viewports unless platform-specific
